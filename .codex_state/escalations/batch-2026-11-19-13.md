## Finding (escalations/ssh_secure.behaviour.md)
- **What the class does:** it sets `ClientAliveCountMax 0` with a 14400 s interval, meaning "end idle sessions".
- **On the node:** OpenSSH 9.6 says, in the node's own sshd_config(5), "Setting a zero ClientAliveCountMax disables
  connection termination". A session idle 30 s under a 10 s interval stayed connected. The reviewer reproduced it.
- **Options:**
  - A, `ChannelTimeout` (recommended);
  - B, `UnusedConnectionTimeout`;
  - C, a nonzero count (it ends unresponsive clients only);
  - D, a shell TMOUT;
  - E, no fix.

  More than one design, so it is escalated, not fixed.

## Local change #6 (rules/local_changes.md)
- **The defect:** filesystem_sec managed a listed command that is a link (24.04: nc, telnet, ftp through
  /etc/alternatives) as the link, which has no mode, so anyone could run the program.
- **The fix:** `links => follow`.
- **Evidence:** before, an ordinary account ran all three (20261119T014403Z); after, it is denied and the sudo account
  runs them (20261119T015305Z).
- **Reviews:** Phase 1 PASS 20261119T015206Z, Phase 3 PASS 20261119T015748Z.
- **Production use:** node_base declares the define, so every production node statement carries the change.
