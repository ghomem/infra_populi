## Production cutover (HQ 2026-11-17 ruling 3) — checks before migrating a class on production machines

| # | class | before cutover | why | source |
|---|---|---|---|---|
| 1 | openvpn_server / network_vpn (the VPN gateways) | On one gateway, read the `service_provider` fact and the running OpenVPN unit (`systemctl list-units 'openvpn*'`). | On a systemd host the baseline cannot compile against puppet-openvpn 8.3.0 (production's version): the duplicate unit and the missing `Service['openvpn']`. So the gateways run other content or are not systemd; the migrated class manages `openvpn-server@puppet_infrastructure`. | escalations/openvpn_server.md "HQ ruling 5" item 4 | HQ 2026-11-17 ruling 3 |
| 2 | nginx_base (with puppet-nginx 8.4.0) | The modules-enabled include now comes from the module (`include_modules_enabled => true`, ruled), as `include /etc/nginx/modules-enabled/*.conf;`. nginx_base's own `*` prepend is gone. A file in modules-enabled without the `.conf` suffix is no longer loaded (Debian packaging ships only `*.conf`). Check on one frontend: `ls /etc/nginx/modules-enabled`. | phase3 nginx_base run 1 (baseline content: 2 includes, nginx refused a dynamic module) and run 2 (ruled change: 1 include, nginx -t ok); rhel9 review: 1 include on RedHat | HQ batch-8 ruling 1 |
| 3 | nginx_base + nginx_frontend_mail (mail/stream frontends on Ubuntu 24.04) | On 24.04 the `nginx` package carries no dynamic modules. A mail/stream frontend needs `my_configs => {package_name => 'nginx-core', mail => true, stream => true}` (nginx-core depends on libnginx-mod-mail/-stream) or the libnginx-mod packages. With `stream => true`, puppet-nginx 8.4.0 also renders a stream access_log without a format, which nginx refuses: it waits on HQ's ruling (escalations/nginx_base.md, second section). | nginx_frontend_mail harness runs 2026-11-17 (module already loaded) and 2026-11-18 (log format is not specified) | batch-8 report; HQ batch-8 ruling 1 |
