# Engine diagnosis — one-page summary (2026-10-26)

Full report: `2026-10-26-engine-diagnosis.md`. Data: `fleet_class_usage.md`, `metrics.csv`. This was a read-only run; nothing outside `.codex_state/diagnosis/` was changed.

**State.** 31 of 87 classes are done (git, tracker and order file agree), 7 are blocked, 1 is gated, 1 is owner-validated and 47 are pending. Three classes used in production are missing from the plan entirely: `gnome_lock_screen`, `firewall_ipv6_drop_policy_desktop` (both used by the desktop fleet via `meaningful_desktop`) and `rsyslog_apparmor_exception`. The first-pass engine is fast on easy classes (~6.5 min wall per "validated unchanged" class), but **zero classes of complexity ≥6 are done**, and GREEN does not yet prove what it claims.

## Top 5 bottlenecks
1. **Blockers are discovered one Codex run at a time.** The 121 stored agent runs include 37 compile failures and 9 apply failures; 11 plan-fix commits and 11 block commits followed. The audits show 50 of the 59 not-done classes are reachable on the current VMs once ~23 plan fixes, ~17 Forge pins, 6 baseline-syncs and one lab-master fixture change are made up front.
2. **The GREEN gate has holes.** Run 2 accepts exit code 2, and the regex misses `executed successfully`. `packages_base` (59 server/desktop node statements) is predicted to pass GREEN while re-running `apt_update` every run. There is no composition compile, so `filesystem_yum` already breaks `node_base` on RedHat with a duplicate declaration, unnoticed.
3. **Per-class overhead.** Each revert takes ~120 s, ~33 s of it a GRUB recordfail timeout baked into the baseline. There are ≥2 reverts per class (17 for 8 classes). Codex spends 60–80% of its ~29 commands and ~68 k tokens re-orienting, because the wrapper gives it no context.
4. **Order ignores the fleet.** All 58 servers declare `node_base`, and its closure (packages_base, firewall_secure, sysmon_base, filesystem_apt, puppet_boot_run…) is pending. Meanwhile 4 of 7 blocks and 5 greens went to classes with no node-file declarations.
5. **Nothing is measured or durable.** Logs have no timestamps and are untracked, reviewer verdicts are not stored, and the Codex runbook and the Puppetfile live outside the repo. The hazard checklist exists in three diverging copies. The toolchain changed (Codex 0.159.2, gpt-6.1-sol, a plugin skill) with no decision entry.
